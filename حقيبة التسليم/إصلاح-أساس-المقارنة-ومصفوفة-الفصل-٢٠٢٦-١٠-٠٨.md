# إصلاح أساس المقارنة ومصفوفة الفصل — ٨ أكتوبر ٢٠٢٦

## النتيجة الحقيقية التي غيّرت التحقيق

حملة `2026-10-08T15-11-17` (وضع `no-gadget`) أعطت أول سلسلة مكتملة
مثبتة: `SIGN-VERIFY=SIGNED_VERIFIED` ثم `ADB-DEPLOY=INSTALLED` مع
`post_install_identity=MATCH` (البايتات والشهادة يطابقان النسخة)،
واستبدال الحزمة المشتركة للمستخدمين `[0, 95]`، ثم انهيار العملية
`SIGABRT` دون أي أثر لأداة Gadget. النتيجة العلمية: Gadget ليس شرطًا
للانهيار، ولم يعد منطقيًا مطاردته قبل فصل المسبار عن إعادة البناء.

## عطلان في المنصة كشفتهما الحملة نفسها

1. **تخطي جولة الأساس دون أساس صالح.** كانت الجولة تُتخطى لمجرد وجود
   ضابط عامل مراقب، حتى عندما كانت هويته غير مربوطة بالأصل
   (`ORIGINAL_RUNTIME=IDENTITY_UNVERIFIED`) — فبقي الطرف الأصلي غير
   مختبَر أبدًا.
2. **تسمية المقارنة `CONTROL_HEALTHY` دون أساس.** مع ضابط غير موثق
   الهوية خرجت المقارنة `CONTROL_HEALTHY_INSTRUMENTED_CRASH` والنصيحة
   «الآلية مرشحة» — وهي تسمية غير مبررة قبل أي فصل.

## الإصلاح

- `tools/reelsec/reelsec.py`: جولة الأساس لا تُتخطى إلا عندما يكون
  الضابط مربوط الهوية بالأصل (`verified=True`)؛ وإلا تعمل الجولة
  الصالحة (الأصل الموقَّع بمفتاح الاختبار نفسه عبر `install -r`
  فقط). توحيد اسم الاسم المستعار بين التوقيع والأساس. فرع
  `repack-only` في مرحلة النسخ. أمر `isolate` الجديد وتشغيل المصفوفة
  `run_isolation_matrix`. أوضاع `platform` تتحول للمصفوفة عند وجود
  `REELSEC_ISOLATION_MATRIX`.
- `tools/reelsec/runtime_health.py`: المقارنة ذات الضابط غير الموثق
  تخرج بحالات `CONTROL_UNVERIFIED_*` الأربع دون أي إسناد؛ والحكم
  والحالة والتراجع والنصيحة التالية تعكس ذلك؛ ونص المرشح في المسار
  الموثق أصبح يسمي «تغييرات النسخة غير المفصولة» مع إحالة للمصفوفة
  بدل التسمية العامة.
- `tools/reelsec/instrumented_copy.py`: وضع `repack-only` — إعادة بناء
  بصفر تغييرات (لا مسبار ولا Gadget) مع رفض مغلق لأي أثر.
- `tools/reelsec/isolation.py` (جديد): خطة المصفوفة (A/B/C أو جزء
  منها، ورفض Gadget مغلق)، سجل الذراع (بصمة النسخة والشهادة ونجاح
  التثبيت والهوية والمعرفات والدليل المربوط بالجلسة وموقع الانهيار
  والنتيجة)، وقواعد القرار: الأصل ينهار => خارج تغييرات ReelSec؛
  A سليم وB ينهار => مرشح إعادة البناء/التوقيع؛ A وB سليمان وC
  ينهار => مرشح مسبار القياس؛ الكل سليم => لم يتكرر الانهيار؛ وأي
  ذراع ناقص => غير محسوم دون تخمين.
- `tools/reelsec/orchestrator.py`: تجميع يقود من وثيقة القرار أولًا،
  وخط `run_isolation` (فحص أمان ثم مصفوفة ثم تجميع ثم نشر).

## الضمانات

- لا Gadget في المصفوفة (رفض مغلق بيئيًا وبالبيان).
- لا إزالة ولا مسح بيانات إطلاقًا (ذراع غير متوافق يُحجب ويُسجَّل).
- لا حملة أثناء الإصلاح.
- المجموعة الكاملة: 402/402 (44 اختبارًا جديدًا، منها تشغيل مصفوفة
  كامل على جهاز مزيَّف ينتهي إلى `TELEMETRY_PROBE_CANDIDATE`).

## أمر واحد فقط من الهاتف

```sh
git pull --ff-only && REELSEC_ISOLATION_MATRIX=ABC python3 tools/reelsec/reelsec.py platform ./original.apk
```
