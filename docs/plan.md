# خطة عمل APKForge الاحترافية: منصة متكاملة لهندسة وتوقيع APK

> وثيقة حاكمة: أي تعارض بين هذه الخطة وأي برومبت لاحق يُحسم لصالح الخطة ما لم تُعدَّل صراحةً.

## 0. الملخص التنفيذي والقرارات المثبتة

- **المنتج:** منصة مفتوحة المصدر (Apache-2.0) لفك وتحليل وتعديل وبناء وتوقيع APK، بواجهة ويب وREST/WebSocket وCLI.
- **القاعدة الحاكمة:** لا بناء من الصفر — دمج وتوحيد أفضل البدائل المجرّبة، وطبقتنا رقيقة (موصلات وعقود وواجهات).
- **القرارات المثبتة من المستخدم:** (1) إعادة هيكلة المستودع حول المنصة مع أرشفة العمل السابق، (2) التسليم الأول خطة عمل مفصلة (هذه الوثيقة)، (3) دمج عمل ReelSec كإضافة توقيع وتحقق، (4) التشغيل على عقدة واحدة عبر Compose.
- **أهم تصحيح فرضه التحقق:** إسقاط uber-apk-signer من النواة لركوده (~٤ سنوات بلا صيانة) واستبداله بـ apksigner/apksig الرسمية.
- **التعديل الثاني (العائلات الديناميكية):** إضافة ثلاث عائلات أولى: استخراج الكود وقت التشغيل (A)، فك الـVM والمحاكاة الأصلية (B)، وأبحاث RASP المضبوطة (C) — مع حكم NPatch (إضافة معزولة، GPLv3) واستبعاد SRPatch X المسبب (مكتبة مغلقة مستخرجة بلا رخصة).
- **التعديل الثالث (مسار حماية المحتوى D):** خدمة السلم الطبقي FLAG_SECURE ←→ Widevine/TEE: تحديد الطبقة المستخدمة فعليًا ثم اختبار إيقافها في المختبر — مع حد TEE الصريح (توثيق الاعتماد دون تجاوز).
- **التعديل الرابع (مصفوفة التغطية ودراسة ReelShort):** §4.5 يربط كل حزمة أدوات بهدفها (Ghidra/Rizin للأصلي، Frida/QBDI للسلوك، Unidbg/Unicorn للمحاكاة، Androguard/JADX/Apktool للـDEX) + دراسة حالة منهجية: أين يحمي اشتراك ReelShort — بحدود دفاعية صريحة.
- **التعديل الخامس (PCAPdroid):** §4.6 يدمج التقاط الشبكة (SNI/DNS/URL/IP + PCAP/HAR + فك TLS المدعوم) كأداة مختبر خارجية (GPL-3.0) تُغذّي فرضيتي API/entitlement في دراسة ReelShort.
- **التعديل السادس (تقنيات الهجوم دفاعيًا):** §4.7 يوثق التقنيات الست (Patch/Hooking، توقيع/PMS، Xposed، Native، Frida، Billing) كنماذج تهديد لاختبار مقاومة تطبيقك — مع أحكام الأدوات (CorePatch وobjection وReVanced كنموذج معماري) واستبعاد فئة القرصنة.

## 1. الرؤية والنطاق

### 1.1 داخل النطاق

فك التجميع (موارد + Smali + Java)، التحليل الأمني الآلي (MASVS)، التحرير، إعادة البناء، المحاذاة، التوقيع v1–v4 والتحقق، المشاريع متعددة المستخدمين، المهام غير المتزامنة مع بث حي، نظام إضافات، CLI، نشر Compose بنقرة واحدة، ومختبر ديناميكي معزول (استخراج DEX وقت التشغيل، محاكاة وتحليل أصلي، اختبار RASP للأهداف المملوكة/المصرح بها فقط)، وتحليل مسار حماية المحتوى (FLAG_SECURE ←→ Widevine/TEE) بالمنهجية نفسها.

### 1.2 خارج النطاق (صراحةً لمنع التمدد)

لا Kubernetes إنتاجي في المراحل 0–2 (تُبنى الجاهزية فقط)، لا سوق إضافات عام قبل المرحلة 4، لا تكامل VirusTotal افتراضيًا (اختياري لاحقًا)، لا دعم iOS، لا تجاوز لحمايات التطبيقات لأغراض غير دفاعية (تُوثَّق سياسة استخدام مسؤولة)، ولا إنتاج أو توزيع أدوات/إعدادات تستهدف تطبيقات طرف ثالث بعينها — أبحاث RASP دفاعية (اختبار تطبيقاتك أنت) داخل المختبر المعزول فقط، وأبحاث مستوى النواة مقيدة بالبوابة البحثية (توثيق + عزل + تشغيل يدوي مصرح)، ولا أدوات استخراج مفاتيح أو CDM أو خوادم تراخيص (امتثالًا لقوانين مكافحة الالتفاف) — الكشف واختبار السلوك فقط.

## 2. الدستور: القواعد الحاكمة (10)

1. **الدمج قبل البناء:** أي قدرة لها بديل ناضج تُدمَج — يُمنَع إعادة تنفيذ فك تجميع أو توقيع أو تحليل.
2. **النضج المشروط:** لا يُعتمَد مشروع بلا إصدار مستقر خلال ١٢ شهرًا أو بلا صيانة نشطة، إلا كإضافة اختيارية معزولة.
3. **العقود أولًا:** لا خدمة دون OpenAPI متجمدة الإصدار، ولا إضافة دون Plugin SDK موقع بالإصدار.
4. **كل أداة خلف واجهة:** لا استدعاء مباشر لأداة خارجية من النواة — كلها عبر محوّلات (Adapters) قابلة للاستبدال.
5. **إعادة الإنتاجية:** كل عملية تسجل: الأداة وإصدارها وبصمات المدخلات والمخرجات والأوامر — أي نتيجة بلا أثر تُرفَض.
6. **الفشل الصريح:** لا تخمين ولا قيم افتراضية صامتة — الفشل يُعلَن بسبب وسبب-مضاد (fail-closed).
7. **الأمان تصميمًا:** عزل التنفيذ، لا أسرار في المستودع، حدود موارد لكل مهمة، تدقيق لكل عملية حساسة.
8. **الرخص النظيفة:** النواة Apache-2.0؛ أي مكون GPL/LGPL يُعزَل كخدمة/إضافة اختيارية منفصلة التوزيع.
9. **الجودة البوابية:** لا دمج دون اختبارات خضراء وتغطية حدّية وفحص أمني ومراجعة عقد.
10. **التوثيق مع الكود:** كل دفع يحدّث التوثيق المتأثر — توثيق متخلف يُعامَل كعطل.

## 3. الموانع (16)

1. ممنوع إعادة كتابة فك تجميع أو توقيع أو محاذاة من الصفر.
2. ممنوع اعتماد أداة راكدة في المسار الحرج (الحد: إصدار خلال ١٢ شهرًا).
3. ممنوع GPL في النواة أو التوزيعة الافتراضية (عزل اختياري فقط).
4. ممنوع أسرار أو مفاتيح أو رموز في الكود أو الصور أو السجلات.
5. ممنوع تنفيذ أدوات بصلاحيات مرتفعة أو خارج العزل المحدد.
6. ممنوع عمليات مدمرة افتراضيًا (حذف جماعي، مسح بيانات) دون تأكيد صريح وتدقيق.
7. ممنوع كسر عقد API أو Plugin SDK دون ترقية إصدار رئيسية ومسار هجرة.
8. ممنوع دمج باختبارات حمراء أو تغطية دون الحد أو تحذيرات أمنية حرجة.
9. ممنوع تبعية غير مثبتة الإصدار (لا `latest` في الإنتاج — تثبيت + lockfiles + SBOM).
10. ممنوع واجهة دون عربية RTL كاملة منذ اليوم الأول (مع i18n للإنجليزية).
11. ممنوع نشر صورة حاوية دون فحص ثغرات وتوقيع إثبات (attestation).
12. ممنوع ادعاء أمني أو سببي لا تدعمه أدلة مسجلة (تقارير MASVS بأدلة قابلة للتدقيق).
13. ممنوع أي تحليل ديناميكي خارج المختبر المعزول أو على هدف غير مملوك/مصرح به كتابيًا.
14. ممنوع شحن حمولات تجاوز RASP جاهزة ضد تطبيقات طرف ثالث — المسموح أطر وتقنيات عامة للاختبار الدفاعي فقط.
15. ممنوع دمج مكتبة مغلقة المصدر أو مستخرجة بلا رخصة مثبتة (قاعدة SRPatch X: الاستبعاد المسبب).
16. ممنوع شحن أدوات استخراج مفاتيح DRM أو CDM أو خفض L1 إلى L3 — الكشف واختبار سلوك التطبيق المملوك فقط.

### 4.3 عائلات التحليل الدينامي واستخراج الكود (التعديل الثاني)

| العائلة | السؤال | الأدوات المعتمدة | الوضع |
|---|---|---|---|
| A — استخراج الكود | DEX مشفرة → تشغيل → DEX حقيقية → استخراج | FRIDA-DEXDump (كلاسيكية مجربة) + clsdumper (٩ استراتيجيات + مضاد anti-Frida) + خط إصلاح DEX (فحص → استخراج → إصلاح → تحقق) | إضافات مختبر |
| B — فك الـVM والأصلي | تعليمات وهمية → مفسّر → دلالات أصلية → استرداد التدفق | Ghidra + Unidbg + QBDI + angr وUnicorn خلفية معزولة (GPL-2.0) | خدمات معزولة |
| C — أبحاث RASP | كشف Frida/تصحيح/روت/سلامة → إجهاض | Frida مُدارة + LSPlant (معزول، LGPL-3.0) + بوابة بحثية + أبحاث نواة مقيدة | مختبر مضبوط فقط |

**أحكام خاصة:**
- **NPatch** (حقن Xposed دون روت، v1.0.0 نشط): يُدمَج **كإضافة اختيارية معزولة فقط** بسبب GPLv3 — لا يمس النواة ولا التوزيعة الافتراضية.
- **SRPatch X** (قاتل توقيع): **مستبعد بسبب موثق** — يغلّف مكتبة `libSRPatch.so` مستخرجة من مشروع ميت بلا رخصة مثبتة، فيخرق قاعدة المصدر المفتوح والمنع 15. البديل المفتوح: اختبار كشف العبث بتقنيات Frida العامة داخل المختبر للأهداف المصرح بها.
- **DarkDex**: مرشح لم يتحقق بعد — يُدرَس عند التنفيذ ويُعتمَد فقط إن استوفى شرطي النضج والرخصة، وإلا سقط تلقائيًا.
- **Unidbg** نفسه Apache-2.0 لكنه يعمل على خلفية Unicorn (GPL) — فخدمة المحاكاة الأصلية تعمل **معزولة** حكمًا.
- **Frida** (رخصة wxWindows المتساهلة، نشطة، الإصدار 17.x) هي العمود الفقري للديناميكي — تُدار مركزيًا (إصدار مثبت، نصوص مراجعة، أهداف مصرح بها فقط).

**معمارية المختبر الديناميكي:** أجهزة/محاكيات في شبكة معزولة، اتصال Frida عبر قناة مسجلة، كل جلسة تتطلب هدفًا مصرحًا به + حدود زمنية وموردية، والمخرجات (DEX مستخرجة) تدخل خط التحليل الاستاتيكي نفسه بأدلة كاملة.

### 4.4 العائلة D — تحليل مسار حماية المحتوى (التعديل الثالث)

السلم: `FLAG_SECURE ←→ سطح آمن ←→ مخازن محمية ←→ Widevine/TEE` — الخدمة تحدد أي طبقة يستخدمها التطبيق **فعليًا** ثم تختبر إيقافها في المختبر المعزول (أهداف مصرح بها فقط).

| الطبقة | الكشف (تحديد الاستخدام الفعلي) | اختبار الإيقاف (مختبر فقط) | الحد الصريح |
|---|---|---|---|
| D1 نوافذ FLAG_SECURE | مسح smali (`setFlags/addFlags` ‏0x2000) + مسبار Frida يقرأ `LayoutParams.flags` لكل نشاط | خطاف يجرّد العلم + محاولة التقاط قبل/بعد كدليل | per-window: الحوارات والتنبيهات وPiP وخدمات الوصول خارج التغطية |
| D2 سطح آمن ومخازن محمية | `Surface.isSecure` + مفكك آمن (`.secure` و`FEATURE_SecurePlayback` و`MediaCrypto`) + أعلام الحماية | إجبار مفكك غير آمن ومراقبة السلوك البديل | المخازن المحمية عتادية — لا قراءة لها حتى من النواة |
| D3 مستوى Widevine | خصائص `MediaDrm` (المستوى/البائع/الإصدار/SystemID) + وجود `liboemcrypto` + مستوى HDCP (كاشف بمعيار DRM Info) | كشف إشارات الخفض L1←L3 وسلوك التطبيق حيالها | لا مفاتيح ولا CDM ولا تراخيص تُشحَن أبدًا |
| D4 الاعتماد على TEE | كشف StrongBox/Attestation (استاتيكي + إشارات keymaster) | — | **نهائي: TEE جذر ثقة عتادي لا يُعطَّل — التقرير يوثق الاعتماد فقط** |

**أحكام الأدوات:**
- نصوص Frida الجاهزة (CodeShare لتجريد العلم) **مراجع تُراجَع وتُثبَّت** — لا تُسحَب حيًّا ولا تُشغَّل دون مراجعة.
- وحدات Magisk العامة لإسقاط العلم: أدوات بيئة خارجية للمختبر — لا تُشحَن ولا تُوزَّع مع المنصة.
- **pywidevine** (تطبيق CDM بلغة Python، GPL-3.0): **لا يُشحَن** — مرجع بحثي للبروتوكول فقط، والخدمة تكتفي بالكشف واختبار السلوك.
- منهجية الدليل: كل طبقة تُختبَر بمحاولة التقاط/تشغيل قبل الإيقاف وبعده + بصمات — بلا دليل لا ادعاء.

### 4.5 مصفوفة التغطية التحليلية ودراسة حالة ReelShort (التعديل الرابع)

**المصفوفة: كل حزمة أدوات ←→ هدفها التحليلي (لا تداخل ولا فراغ):**

| حزمة الأدوات | الهدف التحليلي | المخرج |
|---|---|---|
| Ghidra / Rizin | مسار DRM والكود الأصلي (مكتبات `.so`، واجهات JNI، مفسّرات VM) | رسوم تدفق + مراجع دوال + نقاط الفحص |
| Frida / QBDI | السلوك أثناء التشغيل في بيئة الاختبار | تتبعات استدعاء + سجلات وسائط + أدلة قبل/بعد |
| Unidbg / Unicorn | مكونات ARM/ARM64 المعزولة (محاكاة دون جهاز) | نتائج تنفيذ معزولة + مقارنات سلوكية |
| Androguard / JADX / Apktool | DEX والـManifest والموارد | كود مسترد + أذونات ومكونات + فروق بايتية |
| كواشف D (MediaDrm/Surface/Buffers) | أين تُفرَض الحماية فعليًا | تقرير طبقي D1–D4 بالأدلة |
| PCAPdroid | حركة شبكة الهدف (SNI/DNS/URL/IP + PCAP/HAR) | أدلة فرضيتي API/entitlement |

Rizin (LGPL-3.0 وبعض مكونات GPL) يعمل **خدمة خارجية معزولة** عبر واجهة عملية — لا ربط ثنائي بالنواة.

**دراسة الحالة: أين يحمي اشتراك ReelShort؟ (تحليل معماري دفاعي)**

السؤال: هل الاشتراك يحمي المفتاح/DRM، أم الـentitlement، أم الـAPI، أم مسار فك التشفير، أم إخراج الـSurface؟ المنهجية طبقة-طبقة مع إثبات لكل طبقة:

| الفرضية | كيف تُختبَر | دليل القبول/الرفض |
|---|---|---|
| المفتاح/DRM | تتبع طلبات الترخيص (PSSH/التحدي) + مستوى Widevine الفعلي أثناء التشغيل المدفوع مقابل المجاني | اختلاف الترخيص/المستوى مع ثبات الباقي ← الطبقة هنا |
| الـentitlement | فحص استجابات الحساب (الحالة المدفوعة) وربطها بالقرار داخل التطبيق | القرار يتبع حقل الاستحقاق ← الطبقة هنا |
| الـAPI | مقارنة نقاط النهاية والمحتوى المُرجَع بين الحالتين | اختلاف المحتوى من الخادم ← الطبقة هنا |
| مسار فك التشفير | تتبع المفكك المستخدم (آمن/غير آمن) ووجود `MediaCrypto` في الحالتين | تغيّر المسار مع الاشتراك ← الطبقة هنا |
| إخراج الـSurface | فحص أعلام السطح والنوافذ أثناء المحتوى المدفوع | حماية إخراج إضافية للمدفوع ← الطبقة هنا |

**ثم الإثبات:** مصفوفة قرار توثق لكل فرضية (مقبولة/مرفوضة/غير محسومة) مع الأثر الكامل — وتُنشر الدراسة كتقرير تحليلي، لا كأداة تجاوز.

**الحدود الصريحة للدراسة:** تحليل معماري بأدلة فقط — لا تجاوز للاشتراك بغرض الاستخدام، لا استخراج مفاتيح، لا إعادة توزيع محتوى، ولا استهداف خدمات الطرف الثالث (المنع 13/14/16 سارٍ).

### 4.6 PCAPdroid — التقاط حركة الشبكة وتحليلها (التعديل الخامس)

**الدور:** أداة المختبر على الجهاز لالتقاط حركة التطبيق الهدف (VPN محلي دون روت)، والمنصة تستوعب مخرجاتها (PCAP/HAR/SSLKEYLOGFILE) كقطع أدلة وتُحلِّلها آليًا.

| القدرة | التفصيل |
|---|---|
| تسجيل الاتصالات | سجل لكل تطبيق: المضيفون والمنافذ وحجم البيانات المرسلة/المستقبلة |
| الاستخراج | SNI وDNS وعناوين HTTP URL وIP من DNS وTLS وHTTP |
| فحص HTTP | فحص الطلبات/الردود وتصدير HAR |
| فك TLS | في الحالات المدعومة (CA مثبتة على جهاز المختبر + mitmproxy محلي) مع ملف SSLKEYLOGFILE |
| التصدير والبث | PCAP مع بيانات التطبيق + بث PCAP-over-IP إلى Wireshark للتحليل الحي |
| إثراء | الدولة وASN من قواعد محلية دون اتصال |

**التصميم التكاملي (نظيف رخصيًا):** PCAPdroid برخصة GPL-3.0 — يعمل **أداة مختبر خارجية على الجهاز** ولا يُربَط بالنواة؛ المنصة تستوعب ملفاته فقط (بيانات لا تُلوِّث الرخصة). الجلسات مربوطة بالهدف المصرح به + حدود زمنية، والملفات الحساسة (تحوي أسرارًا محتملة) تُخزَّن مشفرة بسياسة احتفاظ.

**خدمة دراسة ReelShort:** يغذي فرضيتي الـAPI (نقاط النهاية والمحتوى مدفوع/مجاني) والـentitlement (استجابات الحساب) — المقارنة الآلية بين جلستي capture تسمي الفروق بدل التخمين.

**حدود صريحة:** الالتقاط على أجهزة المختبر للأهداف المصرح بها فقط؛ فك TLS بسلطة شرعية فقط (تطبيقاتك + CA مختبرية)؛ لا اعتماد على الميزات المدفوعة (الجدار الناري/كشف البرمجيات/PCAPng) في المسار الافتراضي؛ ويُحظَر التقاط حركة تطبيقات خارج نطاق التفويض.

### 4.7 تقنيات الهجوم على التحقق من الاشتراك — للاختبار الدفاعي (التعديل السادس)

**المبدأ:** هذه التقنيات هي ما يُهاجَم به تطبيقك — المنصة توثقها لاختبار **مقاومة تطبيقك أنت** في المختبر المعزول، ولا تشحن أدوات تجاوز ولا تستهدف طرفًا ثالثًا (المنع 13/14/16).

| التقنية | أفضل الأدوات المفتوحة (محققة) | استخدام المنصة (اختبار مقاومة) | الحكم |
|---|---|---|---|
| Patch/Hooking لمنطق الاشتراك | objection (GPL-3.0، v1.12.4 نشط) + نصوص Frida مراجعة + ReVanced Patcher **كنموذج معماري** (GPLv3) | مسابر تقرأ قرار الاشتراك وتوثق نقاط الفحص في تطبيقك | أدوات مختبر خارجية؛ كتالوج باتشات اختبار يُؤلَّف نظيفًا (Apache-2.0) ولا تُشحَن باتشات تطبيقات بعينها |
| Signature/Package Manager patches | CorePatch (GPL-2.0-only، نشط 2026: تعطيل تحقق التوقيع + downgrade + توقيع غير متسق) | بيئة مختبر لاختبار كشف العبث والتوقيع في تطبيقك | خارجي معزول — لا يُشحَن |
| Xposed/LSPosed modules | LSPosed (GPL-3.0) + LSPlant (LGPL متحقق) + NPatch (GPLv3 متحقق) | اعتراض Java/ART لاختبار حساسية منطقك للخطاف | بيئة/إضافات معزولة |
| Native hooking (`.so`) | Dobby (Apache-2.0) + ShadowHook (MIT، حتى Android 17) + bhook/ByteHook (PLT) | اعتراض دوال أصلية في وكلاء المختبر | مكتبات متساهلة تُدمَج في الوكلاء |
| Runtime instrumentation | Frida (wxWindows متحقق) + objection (GPL-3.0) | مراقبة/تعديل السلوك أثناء التشغيل للأهداف المصرح بها | Frida نواة المختبر؛ objection أداة خارجية |
| Billing/entitlement | **المسار الرسمي وحده:** License Testing + Static responses (`android.test.*` بما فيها الموقعة لاختبار التحقق) + test tracks | اختبار تنفيذ الفوترة والاستحقاق في تطبيقك بالأدوات الرسمية | **المعتمد الوحيد** — فئة Lucky Patcher (مغلقة + غرض قرصنة) **مستبعدة** (المنع 15) |

**منهجية اختبار المقاومة:** كل تقنية ←→ حالة اختبار على تطبيق مرجعي مملوك (هل يصمد التحقق؟) بدليل قبل/بعد — والناتج تقرير صلابة، لا قدرة تجاوز.

## 5. البنية المعمارية (قرار مهني موثق)

**أحادية نمطية ذات حدود صارمة (Modular Monolith) + عمال خلفية** في المراحل 0–2، بحدود خدمات مرسومة منذ اليوم الأول تسمح بالانقسام إلى Microservices دون إعادة كتابة. المبرر: فريق صغير + عقدة واحدة — والـMicroservices المبكرة تكلفة بلا عائد (يُوثَّق كـ ADR-001).

```
Vue 3 SPA ──HTTPS/WSS──► Nginx ──► FastAPI (نواة نمطية: مشاريع/مهام/إضافات/مصادقة)
                                     │ Adapters فقط │ WebSocket بث
                    ┌────────────────┼──────────────┼──────────────┐
                    ▼                ▼              ▼              ▼
              عمال Dramatiq: [فك: Apktool/JADX] [تحليل: Androguard/Quark/Semgrep]
                             [بناء: Apktool/zipalign] [توقيع: apksigner+إضافة ReelSec]
                             [مختبر ديناميكي معزول: Frida/استخراج/محاكاة]
                                     │ S3 API │ SQL │
                    ┌────────────────┴──────────────┴──────────────┐
                    ▼                                               ▼
              SeaweedFS                                      PostgreSQL 16
```

## 6. عقد الإضافات (Plugin SDK)

- كل أداة = حزمة بإصدار دلالي، واجهة موحدة: `Input → Process → Output` بمخططات Pydantic/JSON-Schema مجمدة.
- الإعلان: ملف `plugin.yaml` (الاسم، الإصدار، الأداة المغلفة وإصدارها، الموارد المطلوبة، الرخصة).
- التنفيذ: عملية فرعية معزولة بحدود (CPU/RAM/مهلة/شبكة مقطوعة افتراضيًا) داخل حاوية العامل.
- التسجيل: سجل داخلي (Registry) بإصدارات مثبتة وتوقيع سلامة لكل حزمة.
- اللغات: أي لغة عبر واجهة عملية (stdin/stdout + JSON) — لا ربط ثنائي مباشر بالنواة.

## 7. واجهات API (ملخص)

REST حسب برومبت المستخدم (v1 مجمدة) + WebSocket للبث + CLI رفيع فوق REST. تُجمَّد العقود في المرحلة 0 ولا تتغير إلا بترقية إصدار.
