# ADR-004: الخلفيات المحلية أولًا في المرحلة 1

الحالة: **مقبول** — التاريخ: 2026-10-08.

## السياق

المرحلة 1 يجب أن تُسلِّم منصة عاملة نهاية-لنهاية (رفع ← فك ← عرض ← تنزيل)
قبل توفر البنية الإنتاجية (PostgreSQL وS3 وCelery/Redis في المرحلة 2)،
ودون تجميد تصميم الخدمات على خلفية بعينها.

## القرار

1. **SQLite** خلف واجهة `SqliteStore` الضيقة (مستخدمون/مشاريع/مهام/
   أرتيفاكت/تدقيق) — لا SQL خارج `core/store.py`.
2. **تخزين ملفات محلي مُعنوَن بالمحتوى** (SHA-256) خلف `BlobStore` —
   خلفية S3 (SeaweedFS) تُطبِّق الواجهة نفسها لاحقًا.
3. **تنفيذ متزامن** عبر `BackgroundTasks` يستدعي `JobService.execute`
   نفسه الذي سيربطه عامل Celery في المرحلة 2 (`workers/celery_app.py`
   جاهز للربط ومستورد بأمان بدونه).
4. **منطق الأعمال بمكتبة قياسية خالصة** (`core/` + `services/`) قابل
   للاختبار بلا شبكة؛ التوقيع والأدوار والتخزين بلا تبعيات خارجية.
5. الإعداد عبر البيئة فقط (`APKFORGE_KEY` و`APKFORGE_DB` و`APKFORGE_BLOBS`
   و`APKFORGE_WORK` و`APKFORGE_PLUGINS`) — لا ملفات إعداد تحمل أسرارًا.

## العواقب

- عقدة واحدة بلا توافر عالٍ في المرحلة 1 — مقبول للتأسيس والمختبر.
- التبديل في المرحلة 2 آلي خلف الواجهات (لا تغيير في الخدمات أو العقود).
- الأنواع بلا محول مربوط (تحليل/توقيع) تفشل بسبب صريح بدل كسر العقد.
