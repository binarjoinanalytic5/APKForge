# ADR-001: أحادية نمطية بحدود صارمة أولًا (مقبول)

التاريخ: 2026-10-08 · الحالة: **مقبول** · المرحلة: 0

## السياق

الفريق صغير والتشغيل المستهدف عقدة واحدة (Compose). البرومبت الأصلي
يقترح Microservices كاملة منذ البداية.

## القرار

نبني **أحادية نمطية (Modular Monolith) + عمال خلفية** في المراحل 0–2، مع:
حدود نمطية صارمة، كل أداة خلف محول، عقود مجمدة — بحيث يصبح الانقسام
إلى خدمات لاحقًا نقلًا لا إعادة كتابة.

## المبرر

- الـMicroservices المبكرة: تكلفة تشغيل وشبكة وملاحظة بلا عائد عند الحمل الحالي.
- الحدود المرسومة منذ اليوم الأول تحفظ خيار الانقسام (قابلية عكس القرار عالية).
- العمال منفصلون أصلًا (عمليات + طوابير) — وهو الجزء الذي يتوسع أفقيًا أولًا.

## العواقب

- إلزامي: لا استيراد عبر النمطيات إلا عبر الواجهات المعلنة (يُفحَص في المراجعة).
- يُعاد التقييم عند: > 3 مطورين متزامنين، أو حاجة عزل نشر مستقل لخدمة.
