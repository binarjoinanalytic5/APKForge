# ADR-002: طابور المهام Celery + Redis (مقبول)

التاريخ: 2026-10-08 · الحالة: **مقبول** · المرحلة: 0

## السياق

المهام الثقيلة (فك/تحليل/بناء) تحتاج طابورًا غير متزامن. المرشحان:
Celery وDramatiq — كلاهما يدعم Redis.

## معيار التقييم (قاعدة: الأفضل اختبارًا)

| المعيار | Celery | Dramatiq |
|---|---|---|
| النضج والصيانة | إصدارات نشطة، مجتمع ضخم | نشط لكن أصغر ووتيرة أبطأ |
| التوثيق والوصفات | موسوعي (canvas، chord، retry) | جيد لكن أقل |
| المراقبة | Flower ناضج | أدوات أبسط |
| البساطة | أثقل إعدادًا | أخف API |
| دعم Redis/RabbitMQ | كلاهما | كلاهما |

## القرار

**Celery + Redis** — ترجيح النضج المُختبَر والمراقبة على البساطة،
تماشيًا مع قاعدة الدمج (الأفضل اختبارًا لا الأحدث).

## العواقب

- `workers/` يعتمد Celery 5.x مع Redis broker + result backend.
- المحولات (`workers/base.py`) تعزل منطق الأدوات عن إطار الطابور —
  فيبقى الاستبدال لاحقًا ممكنًا دون مساس بالإضافات.
